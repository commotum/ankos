## Initial Primary Evidence

### Cubic configuration and direct six-face examples

- Sources: `BOOK:2156,2236-2256`.
- Establishes: the source's strict 3D arrangement is a cubic lattice; the two direct face-neighbor examples output black for respectively any black face neighbor and exactly one black face neighbor. Both use a single-black-cell initial condition. Octahedral limit shape and nested appearance are run observations.

### Full surrounding-cube examples

- Source: `BOOK:2262`.
- Establishes: a second access profile uses all 26 positions sharing a face, edge, or corner with the center and outputs black for exactly one or exactly two black surrounding cells. The single cell and line-of-three are independent seeds.

### Dimension-parameterized compact tables

- Sources: `BOOK:13483-13507`.
- Establishes: in dimension `d` and alphabet size `k`, the face profile uses `self + k*AxesTotal` with table length `k*(2*d*(k-1)+1)`, while the full cube uses `self + k*FullTotal` with length `k*((3^d-1)*(k-1)+1)`. For strict binary `d=3`, these are 14- and 54-case complete product tables. Treating the center as separate is source mechanics, not a hidden read.

### General positional order and display mapping

- Sources: `BOOK:13509-13518`.
- Establishes: arbitrary local offsets in any dimension are sorted lexicographically before context digits are formed. Separately, `Graphics3D` displays black cells as `Cuboid[-Reverse[position]]`. The first fact defines program/table order; the second defines a view mapping.

### Projection evidence remains a view

- Source: `BOOK:13632-13640`.
- Establishes: four thirty-step results are shown from above with nearer cells darker, including exact-three-of-26 variants and different initial blocks. Projection depth/tone does not enter their update rule.

### Named 3D class-4 outer-totalistic presets

- Sources: `BOOK:14263-14273`.
- Establishes: the source computes count over the 26 surrounding positions and combines it with the old center. Parameter triple `(p,q,r)` preserves an old black center for counts in `[p,q]` and births at count `r`; named examples are `(5,7,6)`, `(4,5,5)`, and `(5,6,5)`. These are values/presets of a center-plus-count table unless contrary evidence appears; the moving structure is an observer/run fixture.

## Candidate Case Descriptors to Test

```text
FaceProduct[d=3,k]:
    cases = SelfValue x FaceValueSum[0..6*(k-1)]
    index = SelfValue + k*FaceValueSum
    case_count = k*(6*(k-1)+1)

FullCubeProduct[d=3,k]:
    cases = SelfValue x FullNeighborValueSum[0..26*(k-1)]
    index = SelfValue + k*FullNeighborValueSum
    case_count = k*(26*(k-1)+1)

GeneralFaceContext[k]:
    cases = Alphabet^7 in declared Self-plus-six order

GeneralCubeContext[k]:
    cases = Alphabet^27 in declared `{-1,0,1}^3` order

IgnoreSelfRestriction:
    invariant = outputs constant across Self for equal surrounding aggregate
```

For binary strict profiles, the compact face/full product spaces contain `2^14` and `2^54` rules; the count-only main examples lie in the `2^7` and `2^27` ignore-Self restrictions. General positional tables have respectively 128 and `2^27` input contexts and therefore `2^128` and `2^(2^27)` possible binary rules. These counts are candidate derivations to verify against the complete source and an independent oracle, not new semantic classes.
