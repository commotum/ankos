## Book Excerpts

### Excerpt 1 — whole grid, four directions, old center

- Source: `ref/A-New-Kind-of-Science/A-New-Kind-of-Science.md:2168-2170`
- Context: Chapter 5, `Cellular Automata` introduction and first rule icon.
- Establishes: the configuration is a two-dimensional grid; each cell is updated from the four grid directions, and the typical displayed schema also retains the old center value.

> one can also consider two-dimensional cellular automata that involve a whole grid of cells, with the color of each cell being updated according to a rule that depends on its neighbors in all four directions on the grid

> the new color of the center cell depends only on the average of the previous colors of its four neighbors, as well as on its own previous color

### Excerpt 2 — the ten-case center-conditioned code

- Source: `ref/A-New-Kind-of-Science/A-New-Kind-of-Science.md:2178-2194`
- Context: codes `1022`, `942`, and the page-173 gallery convention.
- Establishes: a single-black seed and center persistence belong to run/rule data; the least-significant displayed case is all-white neighbors with white center, followed by black center, then progressively larger cardinal-neighbor counts.

> The last digit specifies what color the center cell should be if all its neighbors were white on the previous step, and it too was white. The second-to-last digit specifies what happens if all the neighbors are white, but the center cell itself is black. And each earlier digit then specifies what should happen if progressively more neighbors are black.

### Excerpt 3 — the six-case equal-sum rule is distinct

- Source: `ref/A-New-Kind-of-Science/A-New-Kind-of-Science.md:2922-2926`

> The rules involve a cell and its four immediate neighbors. Each successive base 2 digit in the code number for the rule gives the outcome when the total of the cell and its four neighbors runs from 5 down to 0.

### Excerpt 5 — direct five-neighbor implementation and dimensional formula

- Source: `ref/A-New-Kind-of-Science/A-New-Kind-of-Science.md:13469-13494`
- Context: Notes for Chapter 5.
- Establishes: a centered single-black finite realization is separate from the rule; the strict binary rule uses center weight `1`, each cardinal neighbor weight `2`, and ten code digits; the same case-product formula is expressed for dimension `d` and alphabet size `k`.

```text
CAStep[rule_, a_] :=
    Map[rule[[10-#]] &,
        ListConvolve[{{0,2,0},{2,1,2},{0,2,0}}, a, 2], {2}]
```

The direct generalized index is `center + k * AxesTotal`, with table length `k * (2*d*(k-1)+1)`. This is the exact product of the center value and the cardinal-neighbor valuation sum, not a floating average and not the later equal-five-value sum.

## Construction Model

- DOMAIN: expected discrete `t+2D`.
- Configuration/support: expected total labeled square-grid support, with any finite computation realization and exterior policy explicit.
- ALPHABET: expected finite typed labels; strict chapter profile initially binary, with multicolor variants separately evidenced.
- FRONTIER: expected all sites in one old time slice.
- NEIGHBORHOOD: explicit ordered displacement schema over square-grid topology; strict four-neighbor versus center-inclusive and diagonal variants must remain distinct.
- RULE: one of three distinct closed descriptions over the same five-position read: (a) a complete 32-context ordered table; (b) the chapter's 10-case product of the center value and exact cardinal-neighbor count; or (c) the later six-case equal sum of center plus four cardinal values. Compact forms are validated factorized representations of qualifying exhaustive tables, never aliases for each other.
- UPDATE: expected one same-site label write per firing locus, committed snapshot-parallel while support/topology remain fixed.
- Successor: expected one deterministic configuration per valid event; fixed points do not imply native halt.
- Seed/realization: separate exact initial configuration, constructors/laws, finite work window, boundary/exterior values, horizon, and viewport.
- Observers/relations: slices, outlines, areas, growth rates, behavior classes, invariant-state constraints, art, biology, emulations, and renderings do not feed execution.
