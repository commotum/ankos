## Construction Model

### Immutable mathematical definition

```text
DifferentialSystemSpec {
  independent_variables: ordered nonempty ContinuousVariable[Real],
  dependent_fields: ordered nonempty FieldSymbol[codomain,components],
  parameters: ordered exact/declared values,
  equations: ordered nonempty Equal(lhs,rhs),
  operator_registry_version
}

PDEProblem {
  system_id,
  continuous_region,
  side_data: ordered conditions on named loci/hypersurfaces/identifications,
  solution_concept,
  required_regularity
}

Solutions(problem) = {
  functions in the declared solution class satisfying every equation on the
  interior and every side condition on its declared locus
}
```

Equation-family identity excludes region/data/concept. Problem identity includes them. A scalar formula that happens to satisfy a problem is a solution witness, not the equation or full solution set.

### Continuous variables, fields, and domains

- Independent variables are bound, ordered real variables with explicit roles only where needed. `t` is not automatically privileged; a time role is required for an IVP/flow query.
- Dependent fields have declared scalar/vector/complex codomains and components. The strict profiles use one real scalar field; supporting physics requires the general schema not to hard-code that restriction.
- A continuous region is structural mathematical geometry—interval/product/whole Euclidean space or a later closed region predicate/stratification—not a finite integer grid.
- Named boundary strata, initial hypersurfaces, and paired periodic faces/loci are explicit. Infinite space has no ghost-cell policy.
- Strict whole-line Gaussian interpretation is a labeled inference from formulas and the `(-infinity,infinity)` energy context, not a silently asserted finite segment.

### Closed differential syntax

- Reuse T41 exact/declared numeric literals, algebra, elementary/special primitives, domains, and branch/version records.
- Add bound `IndependentVarRef`, `FieldRef(field,arguments)`, and `PartialDerivative(expression,multi_index)` nodes. Multi-indices name bound variables and nonnegative orders; arity, variable binding, component types, and equation dimensions are validated.
- Equations are ordered structural `Equal(lhs,rhs)` records. Systems may share fields/parameters but cannot contain callbacks, strings, `eval`, host CAS objects, or trusted derivative functions.
- Temporal/spatial order analysis is derived from the AST. It drives Cauchy-data validation but never rewrites the system into a fake step rule.

### Side data and solution concept

- Side data are typed trace relations: value/Dirichlet, normal derivative/Neumann, Robin/general closed trace relation, initial Cauchy derivative data, or periodic identification. Each names its locus, field/component, derivative order, expression/value, and compatibility scope.
- For temporal order `m`, a Cauchy profile normally supplies compatible traces through order `m-1`. Diffusion needs `u(0,x)`; wave/nonlinear profiles need `u(0,x)` and `u_t(0,x)`.
- The literal diffusion-plus-zero-velocity caption is recorded as incompatible redundant data rather than silently dropped or accepted.
- `Classical(required_derivatives)` is the directly evidenced first profile. `Weak` and `Distributional` are closed principled-extension tags with explicit backend support status; they are never coerced into classical pointwise verification.
- Too little/much data, compatibility failure, and unknown well-posedness are typed problem-analysis results, not constructor guesses.

### No native transition state

- Native T45 has no source/frontier, neighborhood read, local result, commit, successor, or halting rule. It adds no update-algebra member.
- The immutable problem contains all information defining its solution set. A solver's mesh, time integrator state, nonlinear iteration, or residual history is algorithm work, not mathematical state.
- A well-posed IVP can derive a continuous flow/restriction operator. Its Cauchy state at time `tau` contains the field traces required by temporal order. This is a continuous relation whose existence/uniqueness scope must be proved or declared, not a sequence of T01/T44 events.
- A query at finitely many times evaluates/restricts a solution; sample count does not define evolution semantics.

### Query and result algebra

Closed requests include:

- candidate verification on a declared scope and solution concept;
- solve/model-set query with claim region and completeness target;
- point/restriction/sample evaluation of a referenced solution;
- existence, uniqueness, regularity, singularity, maximal-domain, domain-of-dependence, conservation, and stability properties;
- derived-flow or background-reduction claims with replayable premises.

Typed results include:

- `ExactSolutionWitness(function,scope,derivation_or_certificate)`;
- `CertifiedSolutionEnclosure(scope,enclosure,error_certificate)`;
- `ApproximateNumericalSolution(realization_id,interpolant_or_samples,error_claims)`;
- `MultipleSolutionWitness(distinct_verified_witnesses)`;
- `NoSolution(replayable_certificate)`;
- `UniqueSolution(certificate,scope,concept)`;
- `SingularityWitness` or bounded regularity failure;
- `Unknown`, `Unsupported`, `ResourceLimit`, `NumericalInstability`, `NonConvergent`, and `InvalidProblem`.

One witness proves existence only. Two distinct verified witnesses prove nonuniqueness only. Solver failure and bounded search prove neither nonexistence nor singularity. A finite sample cannot prove function equality.

- Finite difference, finite element, method of lines, pseudospectral, symbolic/analytic, and future algorithms are versioned strategies, not branches in mathematical identity.

- Work traces record nonlinear/linear iterations, adaptive steps, rejected steps, mesh refinements, residual histories, and resource use. They never feed back as hidden problem data.

### Native finite-difference relation

The Notes code normalizes to

```text
u[j,n+1] = 2*u[j,n] - u[j,n-1]
           + dt^2 * ((u[j-1,n]-2*u[j,n]+u[j+1,n])/dx^2 + f(u[j,n]))
```

`RotateLeft`/`RotateRight` prove a periodic finite discrete realization. `{u0,u1}` are two sampled time layers, not `(u,u_t)`. Equal Gaussian layers approximate zero velocity under this scheme. `NestList[...,400]` followed by `Map[First,...]` returns 401 initial-inclusive slices; `x=-20..20` by `.1` gives 401 spatial samples. These are exact properties of the related discrete experiment, not strict PDE topology.
